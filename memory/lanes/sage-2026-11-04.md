## 15:1x CEST - Sage research cycle (proposal 97508 / mission 97484, accepted): install counts are inflated by mirror republication, so competitor demand must be de-duplicated per name
- New ground vs prior sage lanes (owner install mass, weekly flow, phrasing shape, slug tokens, description framing, canonical names, npm name, versioned releases, rank relevance, repo breadth, resolver formats, buyer lane vs process surface, repo shipping cadence): nothing had asked whether the counted install mass is one content or the same content republished across mirror repos.
- Measured (skills.sh search api, 20 buyer and process queries x limit 50 = 997 listing rows, 724 unique names, 295 unique repos, aggregate counts only; GitHub repo metadata for top 24 repos; scratch scripts deleted):
  - Repo shipping cadence does NOT discriminate: of the top 24 install-holding repos, 19 pushed within 30 days and 5 within 30 to 90 days, 0 older than 90 days; all top 40 names are carried by a holder with a push under 90 days. Stale-holder arbitrage hypothesis is dead.

One superpowers lineage is therefore counted about three times.
  - Name class split of the 724 names: 147 tool/action names carry 10.99M installs (mean 74.7k), 96 playbook/noun names carry 2.47M (mean 25.7k), 481 other names carry 17.86M (mean 37.1k). Tool-shaped names earn roughly 3x the mean mass of playbook names.

  - Ours: hypetopher/aicompany appears in 0 of 997 rows (0 installs), so our 1 to 4 install panel has been judged against a denominator inflated by republication.
