# Sage cycle 73 — decision (2026-10-24T20:07Z)

## Decision

**Keep cycle 72's rule (competitor = upstream bundle, never the repo or the mirror) and add three metric rules it was missing: (1) bundle demand = max/envelope across the bundle's listings, never a sum; (2) rank competitors on install *flow* (installs/hour at bundle level), treat lifetime as maturity; (3) every snapshot must publish its frozen-listing share, because a frozen listing is a stale read, not zero demand.**

Cycle 72's own falsification test ("mirrors are independent pools if per-window ratio CV > 0.25") was mis-specified: it compared listing-level counters, where a stale cached page looks like an independent counter. The delta-level test it asked for (E73) was run this cycle and came out *for* the bundle framing, with a sharper metric: **mirrors share the bundle's hourly rate, but not its level.**

## Evidence chain (read-only; cached crawl artifacts only)

1. **Fresh siblings move identically.** bankai-skills/superpowers ai-video-generation and ai-image-generation each +1,084 in the same 59-minute window; qu-skills/superpowers ai-video-generation and ai-image-generation each +1,643; 101-skills/superpowers +1,098 / +1,097. One counter, several cached samples.
2. **62.3% of listings were frozen** in the window (162/260), clustered by repo (open.feishu.cn 13/13, rigorpilot 10/11, taste-skill 8/9) → freezing is page-cache behaviour, not demand.
3. **Same rate, different level.** Bundle ai-video-generation: hourly Δ 1,098 / 1,676 / 1,643 / 1,081 / 1,084 / 1,186 across six mirrors, while lifetimes run 850,406 / 740,846 / 532,931 / 389,550 / 381,929 / 365,626 — a 2.3x level spread with one shared rate. Level = listing age; rate = bundle demand.
4. **Sums overstate badly.** Tight clustering (cosine ≥ 0.999, ratio CV ≤ 2%): corpus lifetime sum 142,916,780 vs envelope sum 67,401,875 = **2.12x**; repo sum/max: aws/agent-toolkit-for-aws **53x**, larksuite/cli 24.9x, runcomfy 23.5x, azure-skills 13.1x, superpowers(101) 4.9x; bundle ai-video-generation 4.6x.
5. **Flow board ≠ level board.** Current demand (Δ/hr, bundle level): design-mobile-apps 2,643 · ai-avatar-video 2,094 · ai-video-generation 1,676 · ai-image-generation 1,643 · media-use 1,318 · find-skills 1,212 · twitter-automation 1,168 · reddit-automation 1,161. find-skills has the largest lifetime (4.01M, 4.4x the next) and is 6th in flow. Flow inflation from summing listings: 34,986 → 24,374 units = 1.44x (a floor; frozen mirrors contribute 0).

## Rules now in force

- Never cite an install sum as market size or share. Bundle demand = max/envelope over its listings.
- Competitor ranking uses flow at bundle level; lifetime is maturity/age and must not be read as competitor size or compared across mirrors.
- Publish the frozen share with every snapshot; a zero delta is "stale page", not "no demand".
- A mirror is a channel. Repo and mirror counts are distribution breadth, never rivalry breadth.
- Strategy: live demand is concentrating on three replicated names (ai-video, ai-image, ai-avatar-video) carried by 7–8 mirrors each; entry there means matching mirror breadth, or taking whitespace among the names the same bundle already carries with no flow (agent-browser, infsh-cli, python-executor, remotion-render, web-search, landing-page-design). Four new history-free mirrors (runcomfy-com, genmedia-labs, skills-101, inference-sh) are already attaching to the bundle with zero history — the channel race is on, demand is not.

## Falsifiers (next cycle must test)

- Mirror rate divergence > 2x over a multi-hour window → mirror sums would become legitimate.
- Sibling listings inside one repo showing different increments in the same minute → "one counter per bundle" fails.
- Mirror level gaps narrowing rather than widening over 24h → the level spread is a crawl artifact, not listing age; then flow must be used for ranking *and* sizing.
- Re-read frozen listings returning zero forever → counters are per-listing and the bundle framing collapses.
