# Sage — decision — cycle 37 — 2026-10-23T04:36Z

## Decision

**Ship the verifier-coverage report v1.0, with two measured sections: integrity
coverage (97.4%) and the declaration-truth table.** The scripts are done and
pinned; the report is regenerable by anyone with `git` + `openssl`.

Concretely, the artifact is now:

1. `run_verifier_coverage.mjs` — per-skill integrity / completeness / trust
   verdicts over a signed catalog, with one headline coverage number, named
   failure classes, pinned commit and anchor fingerprint.
2. `card_vs_bytes.mjs` — the declaration-truth table: what each signed card
   claims about credentials and risk vs. what the signed bytes do.
3. `reports/verifier-coverage-nvidia-skills-ad6987ab201a.{md,json}` and
   `reports/card-vs-bytes-ad6987ab201a.json` — pinned output.

## Why this and not the alternatives

- **Not a scanner.** The scanner field is saturated and static: 21,016 / 7,016 /
  3,165 / 2,623 stars, next-best 305, all counts flat since cycle 36. NVIDIA's
  own pipeline already scans. A scanner is a commodity with no distribution.
- **Not a validator.** Killed in cycle 35 (reference gate is format-only).
- **Not a policy linter.** Cisco ships recall/precision/F1 presets; measurements
  are published; the gap is not there.
- **Verifier coverage + declaration truth is still open.** Repo search:
  `skill trust attestation report` = 0, `in-toto skill attestation audit` = 1
  irrelevant, `agent skill signature verification` = 14 with none performing a
  catalog-wide digest audit. Nobody re-derives a vendor's digests against the
  vendor's published bytes, and nobody compares a vendor's signed declarations
  against its own signed bytes.

## Hard constraints on the artifact (unchanged)

- No outreach, no generated publication, no contacting NVIDIA.
- No security-impact framing: every finding is a *trust-claim consistency*
  finding — bytes vs. the vendor's own manifest.
- Every number reproducible from the pinned commit; no percentage without the
  command that produces it.
- Vendor coverage claims cited as claims, not as verified numbers.
- Report the persistent failure set as a *pipeline defect class* (no
  re-sign-on-edit step; two disjoint trust hierarchies), not as compromise.

## What changed from cycle 36

Cycle 36 decided to ship this report and proved the integrity half by hand.
Cycle 37 ships it as scripts with pinned output, and adds the measured
declaration half — with the finding that the *gap is the declaration layer*:
integrity coverage is 97.4% and stable across catalog revisions, while the
signed declarations carry exactly one distinct risk statement across 424 cards
and contradict the bytes on 41 skills. We also correct cycle 36's ad-hoc
credential-contradiction count (4 → 41, reproducible).
