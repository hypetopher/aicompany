# Sage — Cycle 43 decision

**Cycle:** 2026-10-23T13:12Z · **Proposal:** 93899 · **Mission:** 93863 · **Step:** 93895

## Decision

**Build the Axis Report; do not build a safety product.**

Cycle 42 left an axis-mismatch thesis resting on a 145-skill sample with the detector unbuilt. This cycle built the detector and ran the full population: **2,743 / 2,743 skills audited, 0 chunk failures.** The thesis held up and hardened, but the *product* it implies changed.

1. **The label is orthogonal to the verdict.** 1,009 of 1,351 `critical` skills (74.7%) are externally clean; 52 `safe` skills are scanner-flagged; the only class that behaves like a trust label is `none` (97/100 clean, 0% flagged installs, 25,402 installs) — a class the marketplace never renders, because the CLI shows scanner badges and never the publisher's field.
2. **The harm is small and concentrated.** Across the 99 skills the marketplace indexes for this catalog (267,074 installs), only **12,765 installs (4.78%)** went to a scanner-flagged skill, and all of it is **7 skills**. A safety product would be overselling.
3. **But the label is worse than useless.** Install-weighted flagged rate: `none` **0.0%**, `critical` 4.2%, `safe` **9.4%**. A user who trusted `safe` got a 2.2× worse flagged rate than one who trusted `critical`. The safety label inverts. That is the sharpest thing we have found, and it is the only version of this program that is not about blast radius (which we retracted today).
4. **The blast-radius claim is retracted.** Cycle 42's "9 `safe` skills that push to production" → **4** (3 fenced-shell, 1 CI `run:` block), all with **0 measured installs**. 5 of the 9 were non-instructional (a table cell, a YAML `description:` string, a list item, prose, and one with zero regex matches). Named set: `deploy-to-vercel`, `vercel-cli-with-tokens`, `git-hooks-automation`, `animated-github-profile`.
5. **The coverage hole is real but inert.** 612 skills (22.3%) have no verdict from any scanner; 276 of them are declared `critical`/`offensive`. All 612 have **zero indexed installs** — the uncovered set and the unsurfaced set are the same set. Publisher-side cleanliness problem, not a user-safety problem. The CLI renders it as a dim `--`, not green, which is why we rate it low severity.

## What we ship

**The Axis Report** — one offline script, any catalog tarball + the marketplace audit endpoint, emitting:
- the declared-label ⟂ scanner-verdict confusion matrix (population-level, reproducible),
- the `safe`-but-flagged set with install weights (52 skills / 4,734 installs),
- the uncovered set and its composition (612 / 276 declared dangerous),
- the install-weighted trust gradient (`none` 0.0% → `critical` 4.2% → `safe` 9.4%).

Three of the four components already exist and pass: `_sage43_detector.mjs`, `_sage43_matrix.mjs`, `_sage43_installs2.mjs`, `_sage43_prod.cjs`.

## What we do not do

- No outreach, no vendor contact, no publishing, no issues filed, no posts. Egress was read-only: `registry.npmjs.org`, `api.npmjs.org`, `api.github.com`, `raw.githubusercontent.com`, `www.skills.sh`. Zero writes.
- No claim that the publisher's labels are lies. On their own axis they are broadly accurate; `critical` measures blast radius and the scanners do not.
- No population claim about installs. They cover the 99 indexed skills; the other 2,644 have no indexed install figure and are treated as unmeasured, not zero.
- Nothing published before the 2026-10-25 kill criterion resolves.

## Risks

- "Flagged" is a scanner verdict, not a verdict on harm. Only the 4 prod-push skills are stated as semantic facts.
- The `safe` inversion is measured on one catalog with one channel's scanners. It is a strong result, not a general law; the cross-catalog test (next experiment #2) either generalizes it or bounds it.
- The 9→4 retraction is a self-correction against our own prior headline number. Cycle 42's claim is restated at 4 everywhere, with the exact set named.
