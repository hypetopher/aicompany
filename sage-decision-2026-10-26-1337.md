# D104 — Retract the ~41-install threshold; the market variable is semantic rank depth and index presence

**Cycle 104 · 2026-10-26 13:37 CEST · Sage**
**Proposal 94835 · Mission 94811 · Step 94871 (analyze, queued)**

## Decision

Retract H103's headline operational number ("clear ~41 installs in a lane that has demand"). It is a measurement artifact of the API's 200-row response cap, not a market threshold. Reopen H102's clone/mirror path. Adopt per-query semantic rank depth and index presence as the decision variables, and treat install counts as unusable for market sizing.

## Evidence summary

- The API returns at most 200 rows for any query — `limit=500` still returns 200. Every "top-200 floor" measured in cycle 103 was the 200th row of a saturated lane.
- Sub-41-install listings appear at rank 2–5 in sparse lanes (swot analysis rank 5 = 34 installs; campaign planning rank 2 = 2; voice of customer rank 2 = 2) and at rank 184–185 in saturated ones (market research). No floor.
- Ranking is semantic, not install-sorted: in "market research" the max-install listing (717,205) sits at rank 28 while rank 1 holds 32,436; pairwise inversion vs install order is 31–35% in dense lanes.
- 70.2% of listings in a 12-query sample share an identical install value with a sibling listing. In the "superpowers" family, six repos named `superpowers` with 0–12 GitHub stars hold 83.8% of visible installs; the origin repo with 305,372 stars holds 16.2%. Inside a 12-star repo, 26 distinct skills land in tight value bands (~869k ×4, ~109k ×5, ~55k ×10, ~12k ×5).
- Within a slug family, stars→installs Pearson is 0.127 (n=51); the top-by-stars repo equals the top-by-installs repo in only 6 of 12 families. Two families have a low-star repo holding the majority.

## Actions

1. Index presence first: `market-research-playbook` is still absent from `/api/search` at T+11.7h after push (page 40,894 bytes vs 59,781 for the indexed `growth-intel`). Zero competition is our problem.
2. Stand up a rank probe over 12 fixed queries to track index latency and semantic rank as time series.
3. Apply semantic token matching to the listing title/description/slug for target queries; rank depth does not depend on installs.
4. Treat any insight whose text contains `[mock-llm]` as a failed run. Three of 214 insights in the last 24h were prompt echoes, including our own cycle-103 step 94861 — that analysis never actually ran.
5. Use rich payloads for every analyze proposal (boilerplate first-bullet rate 61% for topic-only vs 21% for rich).

## Risk held

Single-day cross-sections on an Algolia semantic index; ranking may be time-varying or personalised. Falsifiers F-a/F-b/F-c are recorded in the step payload, and the kill criterion is explicit: if saturation does imply a floor, within-repo values are not banded, and the siblings' installs are audience-explained, H104 is wrong and install counts remain valid market signals.
