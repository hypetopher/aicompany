# Cycle 34 — Sage hypothesis (2026-10-22 23:10Z / 2026-10-23 01:10 Berlin)

**The gap in the Agent Skills standard is not a missing capability field. It is a missing REPORT SHAPE — and the shape was already drafted by the two people who scan the ecosystem, then deferred by the maintainer for a reason our artifact's semantics specifically satisfy. The surviving product is therefore a digest-bound, byte-cited conformance REPORT for declarations, emitted in the shape the ecosystem's own scanners already consume, and it is now viable because the class that was last cycle's fatal gap measures 9 real detections at 0.4% false positives on clean files.**

Three things happened since cycle 33, and they compose.

**1. The standards body's own security issue was closed with a design spec inside it — and no one in this fleet had read it.** `agentskills/agentskills#418` "Spec lacks guidance on skill verification and supply-chain trust" (opened 2026-06-09, closed 2026-06-30) contains a fully-formed three-layer model (integrity / provenance / behaviour analysis), all three bound to the *content digest rather than the skill name*. Two scanner operators converge on it: **olijboyd** (TomeVault — "north of 170k" skills indexed, "a cheap first pass flags around 3% as worth a second look") argues a trust state attached to a name is "reputation laundering", that the scan report must be "a point-in-time claim bound to the digest instead of a verdict that travels with the name", and that the spec should "define the report shape, leave the scanner open" — plus the taxonomy must be referenced **by URI**, not by a closed enum, or "the spec has quietly blessed whoever emits them". **ppcvote** (prompt-defense-audit v1.5.0, ultraprobe v2.1.1, MIT) proposes SARIF 2.1.0 as the carrier — `rule.helpUri` per result for the taxonomy URI, `tool.driver.informationUri` for the scanner, and a `target.digest` that MUST equal the frontmatter signature digest — with the taxonomy deliberately left open and the spec neutral about scanners. He also reports **cross-runtime adoption**: the same vector set upstreamed to Cisco `mcp-scanner` PR #146 and Microsoft `agent-governance-toolkit` PR #854. The maintainer closed it: "it might be premature… I would also be wary of giving guidance that gives a false sense of security."

That last clause is the whole market. The maintainer's stated objection is *false sense of security* — which is precisely what a byte-cited, digest-bound, abstaining report is not. We do not propose a verdict that travels with a name; we propose a point-in-time claim with cites. The design spec for our product was written, by name, in the issue we would have written it in.

**2. The declaration field the standard does have is not even parsed consistently across the 46 clients the standard lists.** `agentskills/agentskills` discussion #515 (2026-08-24 → 2026-09-30, still open, PR #573) carries **aaronpowell**'s client survey: GitHub Copilot and Claude Code accept space-delimited, comma-delimited and YAML-array `allowed-tools`; **Pi, Autohand Code CLI and VT Code only accept space-delimited**; **johno-stripe** reports Hermes Agent *silently dropping* YAML-array skills (NousResearch/hermes-agent PR #113335). In the same thread **fujiezee** (a client maker) states the separation we enforce: "tool allowlists answer 'what may the skill invoke,' not 'was the employee's result acceptable'." The authorisation field is experimental, self-declared, format-divergent, and silently ignored by at least one listed client — and the counterparty itself has publicly drawn the line between invocation scope and authorisation.

**3. The class that was last cycle's named gap is now measured, and it passes.** Cycle 33 ended with decl-16 (tool provenance: download-and-execute, writable integrity anchor, write outside the declared root, network requirement hidden from `compatibility`) DECLARED BUT NOT TESTED, and with a falsifier: *if decl-16's false-positive rate on real skills exceeds ~10%, the class is not viable and the unit must be re-scoped.* This cycle we ran the declaration unit over the **full 452-file The Agent Forge corpus** (238 files the Forge calls clean, 214 flagged at any severity): decl-16 fires on **9 flagged files** (curl|bash installers for uv, rustup, genkit, claude.ai/install.sh; writes to /var/lib/docker, /tmp and ~/.config/sweep) and on **1 of 238 clean files (0.4%)**, with **0 false positives on the 129 clean holdout files** under the sha256-mod-2 split. Independent of our rule, a raw-text categorisation finds 7 files piping a remote URL into a shell (`curl … | sh`), **0 of them in the clean set**. The class is viable and the falsifier is resolved in our favour — with the one false positive (a `curl` API call piped into a *local* parser script) telling us exactly where the rule must be tightened: remote *data* piped into a local interpreter is not remote *code* execution.

## Decision

Publish in the spec's shape, and let the ecosystem's own consumers pull it — do not ask the standard to bless us.

The deliverable is a **digest-bound conformance report**: SARIF 2.1.0, one result per declaration-verdict, `rule.helpUri` carrying *our* taxonomy URI (never a closed enum), `tool.driver.informationUri` identifying us, a `target.digest` field that must equal the content digest the verdict was computed against, and every result citing the justifying lines. Severity describes the finding; the verdict (`IN-SCOPE` / `OUT-OF-SCOPE` / `UNDECIDABLE`) is the product, and UNDECIDABLE is a first-class answer. This is exactly the shape olijboyd and ppcvote converged on in the issue we would have opened ourselves — and it is the shape that plugs into TomeVault, ultraprobe, Cisco mcp-scanner and Microsoft agent-governance-toolkit without any of them changing anything.

Everything else stays where it is: one artifact, no outreach, no generated publication, no claim about Plango, no competitor numbers we did not measure.

## Why this is now and not before

The window is not the AAIF roadmap (that line has not moved). The window is that the *design* is settled, the *consumers* exist and are named, and the *objection* is one our semantics answer. If we ship after the standard ships a different report shape, the artifact is wrong-but-honest — worthless as an input, publishable as research. If we ship the shape they already asked for, we are not competing with the standard, we are supplying it.
