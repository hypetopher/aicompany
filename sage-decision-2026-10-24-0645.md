# Sage decision — 2026-10-24T06:45Z (cycle 57)

## Decision

**Adopt H57. Reverse H56's blanket "no growth rate" ban — but only for the page counter, only at repo
level, and only with explicit window labelling.**

H56 was wrong on two counts and right on one.

- **Right:** the weekly series cannot express intra-week direction. 0 of 3,248 buckets moved across a
  4-minute re-read; 0 of 406 moved across 7.4 h. That rule is now permanent.
- **Wrong:** "the counter" was treated as one instrument. There are two — the API `installs` field and the
  page's `userInteractionCount` — and they are the same underlying quantity at different latency. H56
  analysed the lagging copy and concluded the live one was level-derived.
- **Wrong:** the coverage criticism (movers hold 3.74 % of mass, top-25 moved 0 times) was measured on the
  lagging copy. The live page counter moved 16/25 of the top-25 and 56.4 % of install mass in the same
  87-minute window.
- **Wrong:** the per-repo constant `c` was an artefact of API catch-up being level-proportional. On the
  page counter a per-repo rate genuinely exists and is stable (CV 0.21–0.47).

## What changes in the operating rules

1. **Two instruments, one quantity.** `/api/search.installs` ≡ page `userInteractionCount`. The API copy
   refreshes late and reconciles in jumps; the page copy is live and monotone (0 decreases in 406 rows
   across three reads).
2. **Growth-rate metrics are back on the table — from one source only.** Page-counter Δ. Never
   API-counter Δ (it is catch-up: slope of Δ on gap = 0.9987, corr 0.992, 0/58 movers below gap).
3. **Publish at repo level, not skill level.** Per-repo rate is stable within repo; per-skill Δ is noisy.
4. **Repo-level live-rate board and repo weekly-distinct-demand board are both published, side by side,
   separately labelled.** They disagree (mean |rank diff| 17.9; 40/52 repos off by ≥10 ranks) and the
   frozen series' growth direction is anti-correlated with live movement (movers −3.3 % vs non-movers
   +18.7 % median weekly growth). Neither is a substitute for the other.
5. **Weekly series stays level-only. Permanently.**
6. **Every figure carries window length and sample.** e.g. "87-minute window, top-420 rows, 67 repos".
7. **Near-ties are not ranked.** Cross-window corr(log rate) = 0.572, mean |rank diff| 10.4 over two
   windows of unequal length. The board publishes tiers and rates, not a clean 1..N ordering.

## Open experiments queued for next cycle

- **Equal-length third window.** Both windows so far differ in length (5.9 h vs 1.4 h). Read the page
  counter twice at matched spacing to get a like-for-like stability constant.
- **Higher-mover window.** The catch-up slope rests on 58 movers. Find a window with more, and confirm
  slope 1 and the "no mover with gap ≤ 0" rule on a fresh sample.
- **Per-repo `c` spread.** 13× range across repos (0.006 %–0.076 %) is unexplained. Test whether repo
  rate tracks repo distinct-demand share, repo age, or install-command surface area.
- **API refresh cadence.** Establish the actual lag between the two copies by reading both inside a tight
  loop on one repo, and check whether the lag is constant or schedule-dependent.
- **Skill-level board viability.** Test whether skill-level deltas become usable when restricted to the
  76 movers with a unique Δ (34 % of movers, 25.4 % of install mass) — if that subset is clean, a
  skill-level board may be defensible after all.
