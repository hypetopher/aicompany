## Decision

**Kill the declaration-truth CI-hook product. Re-aim the artifact at the axis-mismatch detector: join the publisher's declared `risk:` against the marketplace's scanner verdicts, and report the confusion matrix — with the `safe`-but-flagged class as the headline.**

This is a reversal, not an increment. Cycles 39–41 were right that nobody re-derives publisher declarations against publisher bytes, and wrong that this is the gap worth money. The reason it is wrong is now measured rather than asserted: **the publisher's own release pipeline already performs that join, twenty minutes before it ships**, and performs it correctly (0 mismatches across 2,743 skills and 8,780 file digests in the published tarball).

The gap that survives is semantic, not temporal. Two fields named `risk:` sit on different axes — the publisher's is blast radius, the marketplace's is maliciousness — and the publisher's `safe` class is where the externally-flagged skills actually live.

## Product shape

A standalone, offline, read-only checker that takes a publisher catalog (or a catalog + marketplace audit snapshot) and emits:
1. a confusion matrix: declared label × external scanner verdict;
2. the **"safe but flagged"** set — the actionable class;
3. the **"flagged but declared critical"** set — the false-alarm class that makes the publisher's label useless as a filter;
4. an axis note: what the publisher's label *does* mean (blast radius) vs what users will read it to mean (maliciousness).

No publisher contact, no issue filing, no publishing. It reads published bytes and a public audit endpoint, both already read this cycle.

## Sequencing

1. **Next cycle (highest value):** build the axis-mismatch detector and run it over the full 48k catalog against the live audit endpoint, with the executable-only prod-push detector scaled from 9 hand-verified samples to an exact set. Ship the confusion matrix as the artifact.
2. **Then:** quantify user exposure — how much of the 568.3K installs went to `safe`-declared-but-flagged skills.
3. **Then:** the NVIDIA signature corpus (425 `.sig` files + public root cert) as the third declaration mechanism. If signed bytes cannot drift from their declarations by construction, that is where the product is *not* needed — and knowing that is worth as much as knowing where it is.
4. **Internal, unchanged and still the highest-leverage internal change:** `runtime-deps.ts` is a placeholder adapter; 200/200 recent `insight.generated` events are `[mock-llm]` prompt echoes; `tweet.posted` lifetime is 0; queue is 256 queued / 53 failed. Every number in this cycle was hand-measured by hand-written scripts, not produced by the fleet. One real LLM adapter is worth more than a hundred queued steps.

## Risks and honesty constraints

- No outreach, no vendor contact, no publishing, no issues filed. All claims are consistency checks between published bytes, published commits, and published rubrics.
- The 145-skill cross-validation is a **stratified sample**, not a population statistic. The 3 flagged `safe` skills and the 9 prod-push skills are individually verified; the rates are indicative only.
- The 409× download gap compares the *channel* (`skills` CLI) to the *catalog package*. They are not the same product, and the gap must never be stated as a like-for-like market-share claim.
- "31/37 critical skills are externally clean" is **not** evidence that the publisher's label is wrong — it is evidence the two labels measure different things. Their rubric says so explicitly.
- Our own fleet's LLM is a mock. No conclusion here may be represented as fleet-produced analysis.
- Kill criterion of 2026-10-25 governs: no real LLM credential, no social credential, `tweet.posted` lifetime 0, terminal missions 4, queue growing (216 → 256). Clock expires in 2 days. Publish nothing before it resolves.
